# 模型学习三阶段框架

学习一个机器学习模型，容易停在"会调包"或者"记住了公式"的层面。这个框架要求对每个模型过三遍，分别站在三种角色的视角上，逼迫自己把理解做深、做实、做出业务判断力。

三个阶段不要求一次性连续完成，但建议按顺序进行：没有阶段一的原理理解，阶段二的实现容易变成抄代码；没有阶段二的实现经验，阶段三的方案对比容易空谈指标。

## 阶段一：研究员视角 — 模型三要素

目标：能不看资料、独立讲清楚这个模型"是什么、为什么这样设计"。

统计学习中经典的三要素划分：

| 要素                | 要回答的问题                             |
| ----------------- | ---------------------------------- |
| **模型（Model）**     | 假设空间是什么？对输入输出关系做了什么结构性假设？参数化形式是什么？ |
| **策略（Strategy）**  | 优化目标（损失函数/似然/先验）是什么？为什么选这个目标而不是别的？ |
| **算法（Algorithm）** | 怎么求解这个优化问题？有没有闭式解[^闭式解]？用什么迭代方法？复杂度如何？   |

[^闭式解]:闭式解‌是指通过有限步骤的代数运算直接得到的显式数学表达式，无需迭代或数值逼近即可计算 

补充必答项：
- **适用边界**：什么数据/场景下这个模型的假设会失效？
- **演化关系**：它是在解决前一代模型的什么问题？后续模型又是为了解决它的什么问题？（例如 线性回归 → 逻辑回归 → GBDT → XGBoost 这条链上，每一步解决了什么）

产出物：`models/<category>/<model>/01-research.md`，使用 [templates/model-research-template.md](../templates/model-research-template.md)。

## 阶段二：算法工程师视角 — 从零实现 + 调优

目标：不依赖 sklearn/框架的高层 API，手写出核心训练逻辑，并能系统地调参、解释结果变化。

要求：
- **从零实现**：至少实现一次不调库（除了基础的数值计算库，如 numpy）的版本，覆盖前向计算、损失、梯度/更新规则
- **工程细节**：向量化写法、数值稳定性（如 softmax 的溢出处理）、复杂度分析
- **调参实验记录**：不是只贴最终的最优参数，每次实验按"假设 → 改动 → 结果 → 结论"记录，形成可追溯的实验日志
- **baseline 对比**：在一个标准数据集上，给出 baseline 版本和调优后版本的指标对比

代码不在本仓库内直接维护/运行，实现代码放外部 GitHub repo 或 Colab notebook，本仓库只记录链接、关键代码片段（能说明设计决策的片段）和实验记录。

产出物：`models/<category>/<model>/02-implementation.md`，使用 [templates/model-implementation-template.md](../templates/model-implementation-template.md)。

## 阶段三：数据科学家视角 — 业务化与方案对比

目标：能回答"这个模型该不该用在某个具体业务问题上"，而不是停留在模型本身效果好不好。

要求：
- **业务场景映射**：这个模型能解决什么类型的业务问题？有哪些可替代方案（包括非 ML 的规则方案）？
- **指标体系**：离线指标（AUC/RMSE/...）和线上业务指标（转化率/GMV/...）之间的映射关系是什么？什么时候离线指标提升不代表业务指标提升？
- **方案对比**：用决策矩阵对比候选方案，维度至少包括效果、计算/推理成本、可解释性、迭代速度、工程复杂度
- **案例沉淀**：结合真实或模拟的业务 case，写清楚选型理由和踩坑点

这个阶段强烈建议参考 `cases/` 目录下的大厂落地案例，看同一类模型在不同业务场景下的选型差异。

产出物：`models/<category>/<model>/03-business.md`，使用 [templates/model-business-template.md](../templates/model-business-template.md)。

## 两个辅助内容库

- **Papers 库**（`papers/`）：论文阅读笔记，不要求每篇都推进到完整的三阶段模型条目。只有当一篇论文对应的模型值得深入学习时，才在 `models/` 下新建条目，并在论文笔记里反向链接过去。
- **案例库**（`cases/`）：大厂技术公众号/博客的模型落地复盘，结构统一为"场景-选型-指标-踩坑"，关联到具体模型条目，作为阶段三的外部参照。

## 模型条目的最终目录结构

```
models/<category>/<model-name>/
├── 01-research.md         # 阶段一：模型三要素
├── 02-implementation.md   # 阶段二：从零实现 + 调参
├── 03-business.md         # 阶段三：业务化与方案对比
└── README.md              # 条目总览：一句话简介 + 三阶段进度 + 关联 papers/cases
```
